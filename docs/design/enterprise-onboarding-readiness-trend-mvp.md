# Enterprise Onboarding Readiness Trend MVP

Updated: 2026-05-01

Ticket: `KAN-55`

## Purpose

KAN-55 adds a trend report for Enterprise Onboarding Readiness evidence generated by KAN-53.

KAN-52 answers the current state. KAN-53 generates that state on a cadence. KAN-54 monitors whether the artifact exists and is fresh. KAN-55 shows whether the readiness state is improving, declining, or stable over recent artifacts.

## Workflow

File:

```text
.github/workflows/enterprise-onboarding-readiness-trend-report.yml
```

Script:

```text
scripts/control-plane/generate_enterprise_onboarding_readiness_trend_report.ps1
```

Source workflow:

```text
enterprise-onboarding-readiness.yml
```

Source artifact prefix:

```text
enterprise-onboarding-readiness-
```

Trend artifact:

```text
enterprise-onboarding-readiness-trend-report
```

## Triggers

- manual `workflow_dispatch`.
- weekly schedule on Thursday at `14:17 UTC`.

This schedule runs after KAN-53 readiness generation and KAN-54 artifact monitoring.

## Inputs

| Input | Default | Purpose |
| --- | ---: | --- |
| `max_reports` | `12` | Maximum parseable readiness artifacts to include in the trend. |

## Output

The workflow uploads:

```text
enterprise-onboarding-readiness-trend-report.md
enterprise-onboarding-readiness-trend-report.json
```

The trend includes:

- latest readiness status.
- latest readiness score.
- latest stage counts.
- score delta versus oldest analyzed report.
- ready/needs-action/blocked stage deltas.
- count of runs that were ready, needs-action, or blocked.
- skipped runs for missing, expired, or non-parseable artifacts.

## Safety Boundaries

The trend report:

- reads GitHub Actions run and artifact metadata.
- downloads only readiness artifacts produced by the selected workflow.
- parses the sanitized `enterprise-onboarding-readiness.json` file.
- does not read `.env` files.
- does not read provider tokens.
- does not print Authorization headers.
- does not create GitHub Actions variables or secrets.
- does not mutate customer repositories.
- does not mutate provider settings.
- does not dispatch workflows.
- does not alter branch protection.
- does not make onboarding readiness or release governance blocking by default.

## Non-Goals

- replacing KAN-52 current readiness reporting.
- replacing KAN-53 readiness automation.
- replacing KAN-54 artifact freshness monitoring.
- failing releases because onboarding is `needs-action`.
- enforcing release approvals or quorum.
- connecting providers directly.
- creating GitHub Actions variables or secrets.

## Acceptance Criteria

- Local script can generate Markdown and JSON from existing KAN-53 artifacts.
- Workflow can run manually and upload a trend artifact.
- Scheduled workflow is enabled for recurring trend evidence.
- Trend output remains secret-safe and non-mutating.
- Documentation clearly states that trend evidence is not release blocking by default.
