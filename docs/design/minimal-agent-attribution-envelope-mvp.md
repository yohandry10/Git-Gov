# KAN-96 Minimal Agent Attribution Envelope

Date: 2026-06-14

## Decision

KAN-96 adds a minimal attribution envelope to optional Agent Governance requests.

This is not a full agent observability system. It is a small audit contract for:

- `POST /agent-governance/dry-run`
- `POST /agent-governance/evaluate`
- `GET /agent-governance/evaluations`

The goal is to answer who or what asked GitGov for an agent governance decision, which tool/session
originated it, which correlation id links related requests, and which deterministic decision GitGov
returned.

## Product Boundary

GitGov remains manual-first.

KAN-96 does not add:

- MCP server.
- chatbot.
- BYOM.
- autonomous execution.
- provider mutation.
- Deployment Gate behavior changes.
- prompt storage.
- full tool traces.
- agent session replay.
- agent execution graph.
- Action Center writes.

Agent attribution applies only when a customer has explicitly enabled optional Agent Governance.
Manual-only customers and Deployment Gates do not need Agent Governance attribution.

## Request Contract

Agent Governance requests may include:

```json
{
  "attribution": {
    "correlation_id": "corr-kan96-001",
    "parent_correlation_id": "corr-kan96-parent",
    "session_id": "sess-kan96-001",
    "tool_name": "codex-cli",
    "tool_version": "1.0.0",
    "agent_name": "codex-kan96-agent",
    "external_run_id": "github-actions-run-123"
  }
}
```

All fields are optional. If `correlation_id` is missing, GitGov generates an `agcorr_` id.

Validation is deliberately strict:

- only the listed fields are accepted.
- each value is a string up to 128 characters.
- control characters are rejected.
- credential-looking values such as `Bearer ...` are rejected.
- prompts, diffs, source code, raw tool traces, and secret material are out of scope.

## Response Contract

Dry-run responses include:

- `consumer_type=agent_dry_run`
- `attribution`
- `dry_run=true`
- `would_persist_evaluation=false`
- `would_authorize_execution=false`

Formal evaluation responses include:

- `consumer_type=agent_governance` inside `attribution`
- persisted attribution columns
- `evaluation.attribution`
- normal `agent_governance_evaluations` history exposure

Dry-runs still do not create formal `agent_governance_evaluations` rows.

## Persistence

KAN-96 adds attribution columns to `agent_governance_evaluations` through
`supabase_schema_v41.sql`:

- `attribution_id`
- `correlation_id`
- `parent_correlation_id`
- `session_id`
- `tool_name`
- `tool_version`
- `agent_name`
- `external_run_id`
- `consumer_type`

It also adds correlation/session indexes for admin history lookups.

No dry-run table is added in this slice. Dry-run attribution is returned to the caller and recorded
in safe admin audit metadata only.

## Production-Ready Criteria

KAN-96 is ready only if:

- manual-only tenants still return `agent_governance_disabled`.
- dry-run still creates no formal evaluation row.
- evaluate persists attribution and history returns it.
- missing `correlation_id` is generated by GitGov.
- unsafe attribution is rejected without persistence.
- agent keys, revocation, allowed actions, and tenant opt-in still work.
- Deployment Gates are unchanged.
- production smoke proves manual-only plus temporary opt-in behavior and restores settings.
